## Ключевые архитектурные решения

1. **Общее игровое состояние — в `product-core`.** Баланс, копилка, питомец, период нужны всем фичам, а фичи
   не зависят друг от друга. Поэтому:
   - `product-core:domain` — модели и чистый `GameEngine` (все формулы) + интерфейсы `GameRepository`,
     `ContentRepository`;
   - **новый модуль `:app-modules:product-core:data`** — реализации: состояние в DataStore (JSON через
     kotlinx-serialization, атомарная запись), контент из `assets/content/*.json`, Hilt-привязки;
   - фичевые `domain` — use case'ы поверх `GameEngine` + `GameRepository` (как `BuyItemUseCase` в примере README);
     фичевые `data` модули остаются пустыми, если фиче нечего хранить.
2. **Хранилище — DataStore, не Room.** Одно состояние профиля (`GameState`) — один документ; ТЗ 3.2 допускает файловое
   хранилище; у DataStore есть KMP-версия. Добавить `androidx-datastore` в `libs.versions.toml`.
3. **Контент отдельно от кода (ТЗ 2.5.14).** Товары, цели, задания, сюжет недель, словарик, реплики Дзыня — JSON в
   `product-core:data/src/main/assets/content/`. Новое задание = новая запись JSON, без правки логики.
   Тексты UI — `strings.xml` фич.
4. **Задания — data-driven движок из 2 типов:** `choice` (ситуация → варианты с последствиями: дельты баланса,
   мешочков, показателей + объяснение) и `basket` (собрать корзину в пределах суммы). Этого достаточно для
   «игровой ситуации с выбором и последствиями» (ТЗ 2.5.8).
5. **Только тёмная тема.** `FinEduTheme` без светлой схемы, токены и типографика (Commissioner) из макета.
   Конвенция README «превью — `@PreviewLightDark`» меняется на `@Preview` в тёмной теме — обновить README.
6. **Старт-экран** выбирается в `MainActivity` по наличию профиля (`GameRepository`), сейчас там TODO.

### Модели и формулы (`product-core:domain`)

- `Bag { NEEDS, WANTS, SAVINGS }` — «Нужное», «Хочу», «Копилка».
- `GameState`: `profile` (имя игрока, имя питомца, `PetLook(fur, hat)`, `isDemo`), `balance: Dzynki`,
  `savings: Dzynki`, `selectedGoalId`, `period` (номер, доход, `BudgetPlan?`, покупки, пополнения, пройденные
  задания), `pet` (`charge/vibe/calm` 0..100, `xp`, `stage`), `completedQuestIds`, `history: List<PeriodResult>`,
  `ledger: List<LedgerEntry(source, amount)>` — каждое начисление с источником (ТЗ 2.5.4).
- `GameEngine` (чистые функции `GameState → Result`):
  - `confirmPlan(plan)` — сумма ≤ доход, остаток; план меняется до подтверждения;
  - `buy(item)` → `Success(Feedback)` | `NotEnoughMoney(missing, options)`; баланс не уходит в минус (`Dzynki` уже
    это гарантирует);
  - `deposit(amount)`, `previewWithdraw(amount)` → было/стало сумма и срок, `withdraw(amount)`;
  - срок цели = `ceil(осталось / среднее пополнение за период)` (ТЗ 2.5.7);
  - `completeQuest(questId, choiceId)` → `QuestOutcome(Feedback, reward)`;
  - `closePeriod()` → `PeriodResult` (план vs факт по мешочкам, закрыто ли Нужное, отложено, опыт, смена стадии,
    причины) и старт следующего периода с доходом;
  - `grantParentBonus(amount, reason)`; `resetDemo()`.
- Питомец: показатели меняются от решений (Нужное → Заряд, Хочу → Вайб, Копилка → Спокойствие), нижняя граница —
  «устал», не 0. Опыт за неделю: Нужное закрыто +1, отложено >0 +1, уложился в план +1, задание +1.
  Стадии: Малыш → Шустрик (4) → Мастер мешочка (10); опыт не отнимается.
- `Feedback`: дельты баланса / мешочка / показателя, ключ причины, ключ следующего шага (ТЗ 2.5.9).

уголке, «Спокойный режим».

Если отстаём и дальше: (1) тип задания `basket` → все задания `choice`; (2) анимации → статичный `FeedbackSheet`;
(3) «Задания» и «Задание» — один экран; (4) component-тесты → ручные тест-кейсы.

**Трогать нельзя:** шаги 1–12, демо-режим и сброс, сохранение прогресса, раздел для взрослого, контент в JSON,
unit-тесты экономики, подписанный APK.
