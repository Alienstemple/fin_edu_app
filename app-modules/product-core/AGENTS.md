# Product Core Agent Instructions

Эти инструкции применяются ко всем изменениям внутри `app-modules/product-core`.

## API Module Documentation

Каждый API-модуль внутри `product-core` должен содержать `README.md` в корне модуля.

API-модулем считается модуль с путём вида:

- `*/api`

Например:

- `navigation/api`

## README.md Requirements

`README.md` API-модуля должен описывать все публичные контракты модуля:

- публичные интерфейсы;
- публичные классы, модели и value objects;
- публичные функции и extension-функции;
- DI-контракты, если они предназначены для использования вне модуля;
- ожидаемые сценарии использования;
- ограничения, инварианты и важные side effects;
- правила совместимости для потребителей API.

Документация должна быть достаточной, чтобы потребитель API мог понять назначение модуля и правила использования публичных контрактов без чтения реализации.

## Updating API Documentation

При любом изменении API-модуля агент обязан проверить актуальность `README.md`.

Обновляйте `README.md`, если изменение:

- добавляет новый публичный контракт;
- удаляет или переименовывает публичный контракт;
- меняет сигнатуру, поведение или семантику публичного контракта;
- меняет правила DI, инициализации или подключения модуля;
- добавляет новый API-модуль внутри `product-core`.

Если создаётся новый `*/api` модуль, создайте для него `README.md` в том же изменении.

## Domain

`domain` — чистый Kotlin/JVM модуль (без Android SDK). В нём живут доменные модели и игровая экономика:
бюджет, покупки, накопления, питомец, периоды. Не добавляйте в `domain` зависимости на Android, Compose,
Room или `data`-слой. Любая новая формула экономики сопровождается Unit-тестом.

## Verification

Перед сдачей изменений в `product-core` проверьте:

- для каждого `*/api` модуля существует `README.md`;
- новые или изменённые публичные контракты отражены в README соответствующего API-модуля;
- README не описывает удалённые или устаревшие контракты.
